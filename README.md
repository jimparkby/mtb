# KOPI — инвестиции со сдачи

Каждая оплата картой округляется вверх, сдача копится в копилке и одним пакетом покупает BTC, ETH или консервативный рублёвый инструмент по реальному курсу.

## Что сделано

- **Эмулятор оплаты и round-up движок.** Касса принимает сумму, сервер округляет до 1/5/10 BYN с множителем ×1/×2/×5 и кладёт сдачу в копилку (`server/engine.js`).
- **Пакетная покупка по реальному курсу.** Когда копилка набирает порог (10/20/50 BYN) или нажата «Купить сейчас», вся сдача покупается одной операцией. Курс в первую очередь берётся с белорусских площадок — резидентов ПВТ, где пара сразу в рублях: Dzengi (открытый API), затем Bynex (недокументированный эндпоинт страницы обмена). Используется середина между ценой покупки и продажи. Если они недоступны — мировые биржи Binance → OKX → Kraken → Coinbase → CoinGecko (USD/USDT) × официальный курс НБРБ. Площадки опрашиваются по очереди, так что недоступность одной (например, 451 у Binance для серверов в США) не ломает курс. Сервер обновляет курс каждые 5 с в фоне, курс НБРБ — раз в час, в БД пишет не чаще раза в минуту. Если все API недоступны, используется последний известный курс (`server/rates.js`).
- **Живой капитал.** Страница обновляется каждые 5 с: бейдж Live с названием биржи, график стоимости портфеля за последний час, подсветка роста и падения курса и суммы.
- **Дашборд накоплений и цели.** Стоимость портфеля, доходность по каждому активу, копилка, прогресс цели и прогноз в месяцах.
- **Кликабельное демо сценария покупки.** Пресеты покупок, чек, push-уведомления, сброс демо к «неделе покупок Ивана». Демо открывается без входа: каждый посетитель (например, по QR на презентации) автоматически получает свою копию данных Ивана, поэтому зал не мешает друг другу. Гостевая сессия живёт неделю, потом гость удаляется.
- **Аккаунт скрыт.** Вход, привязка карты и пересылка SMS банка доступны по ссылке с `?account` (например, `https://…/?account`).
- **Аккаунты.** Регистрация и вход по email и паролю (scrypt), сессии по токену на 30 дней, ограничение попыток входа (`server/auth.js`). У каждого пользователя свои настройки, цель, копилка и портфель.
- **Привязка карты.** Через платёжного провайдера: номер карты вводится на его странице, KOPI хранит только токен, последние 4 цифры и тип (`server/payments.js`). Поддержан bePaid; для разработки и показа есть тестовый провайдер.
- **Уведомления банка с телефона.** Пользователь получает личную ссылку, телефон пересылает на неё SMS или push банка об оплате («Команды» на iPhone, MacroDroid на Android). Сервер разбирает сумму и магазин, пропускает переводы, пополнения, возвраты и снятие наличных, повтор того же сообщения не засчитывает (`server/sms.js`). Так round-up работает с настоящей картой любого банка без договора с ним.
- **Оплаты от банка.** Эндпоинт для уведомлений банка-партнёра о каждой оплате картой: HMAC-подпись, защита от повтора, идемпотентность по id транзакции.
- **Проведение покупки.** Сдача резервируется → списывается с карты → актив покупает брокер. Отказ в списании возвращает сдачу в копилку; сбой брокера после списания докупается при сверке раз в минуту (`server/purchaser.js`). Пока нет договора с криптоплатформой, работает «бумажный» брокер: покупка записывается по реальному курсу площадки, ордер никуда не уходит (`server/broker.js`).
- **PostgreSQL или SQLite.** Один слой БД с миграциями (`server/database.js`): `DATABASE_URL` → PostgreSQL, иначе SQLite. Старая SQLite-база демо-версии обновляется на месте.

## Запуск

Нужен Node.js 24.

```bash
npm install
npm start          # http://localhost:3000 — демо
npm run dev        # с перезапуском при изменениях
npm test           # тесты на SQLite и на PostgreSQL (PGlite, ставится как dev-зависимость)
```

Полный путь настоящего аккаунта без договоров с банком и эквайером:

```bash
PAYMENTS_PROVIDER=sandbox BANK_WEBHOOK_SECRET=dev-secret npm start
# 1. В приложении: «Демо · Войти» → «Регистрация»
# 2. «Оплатить» → «Привязать карту» (тестовый провайдер привяжет •••• 4242 сразу)
# 3. Скопируйте «Идентификатор карты для банка» и отправьте оплату от имени банка:
BANK_WEBHOOK_SECRET=dev-secret node scripts/bank-tx.js --card <ref> --amount 6,40 --merchant Кофе
```

## Переменные окружения

| Переменная | Что делает |
|------------|------------|
| `PORT` | порт, по умолчанию 3000 |
| `DATABASE_URL` | PostgreSQL (`postgres://…`). Если не задан — SQLite |
| `PGSSL` | `true`, если Postgres требует SSL (внешний адрес Railway) |
| `DB_PATH` | путь к файлу SQLite, по умолчанию `data/kopi.db` или volume Railway |
| `PUBLIC_URL` | адрес сервиса для возврата со страницы провайдера и уведомлений; на Railway берётся из `RAILWAY_PUBLIC_DOMAIN` |
| `BEPAID_SHOP_ID`, `BEPAID_SECRET_KEY` | ключи магазина bePaid — включают привязку карт и списания через bePaid |
| `BEPAID_TEST` | `false` — боевой режим bePaid; по умолчанию тестовый |
| `PAYMENTS_PROVIDER` | `sandbox` — тестовый провайдер без bePaid |
| `BANK_WEBHOOK_SECRET` | секрет подписи уведомлений банка; без него эндпоинт выключен |

## База данных

| Таблица     | Что хранит |
|-------------|------------|
| `users`     | пользователи: имя, email, хэш пароля, `is_demo` |
| `sessions`  | SHA-256 токенов сессий и срок действия |
| `ingest_tokens` | SHA-256 личной ссылки для пересылки уведомлений банка |
| `cards`     | привязанные карты: токен провайдера, последние 4 цифры, тип, статус, `ref` для банка |
| `settings`  | шаг округления, множитель, актив, порог пакетной покупки |
| `goals`     | цель накопления (название, сумма) |
| `payments`  | оплаты: сумма, округление, сдача, источник (`emulator`/`bank`), id транзакции банка; `purchase_id` пуст, пока сдача в копилке |
| `purchases` | пакетные покупки: актив, сумма, курс, количество, статус (`pending` → `charged` → `filled`, либо `failed`/`review`), ссылки на списание и ордер |
| `rates`     | история курсов BTC/ETH в BYN (раз в минуту) |
| `schema_migrations` | применённые миграции |

Копилка — это сдача по оплатам без `purchase_id`. Покупка в одной транзакции резервирует эти оплаты; если списание не прошло, они возвращаются в копилку. Все суммы — в копейках (целые числа).

## API

Без заголовка `Authorization` запросы работают с общим демо-пользователем (так работали старые версии фронта); сайт сам берёт гостевой токен. Со своим аккаунтом — `Authorization: Bearer <token>`.

| Метод | Путь | Описание |
|-------|------|----------|
| POST  | `/api/auth/guest` | своя копия демо без регистрации → `{ token, user }` |
| POST  | `/api/auth/register` | `{ email, password, name }` → `{ token, user }` |
| POST  | `/api/auth/login` | `{ email, password }` → `{ token, user }` |
| POST  | `/api/auth/logout` | завершить сессию |
| GET   | `/api/config` | какой платёжный провайдер и брокер подключены |
| GET   | `/api/state` | всё состояние дашборда |
| GET   | `/api/rates[?refresh]` | текущий курс |
| GET   | `/api/ticks` | курс за последний час для графика |
| POST  | `/api/payments` | только демо: `{ merchant, amount: "6,40" }` — эмулятор кассы |
| POST  | `/api/purchases` | купить сейчас на всю копилку |
| PATCH | `/api/settings` | `{ round_step, multiplier, asset, threshold }` |
| PUT   | `/api/goal` | `{ name, target }` (target в копейках) |
| POST  | `/api/reset` | только демо: вернуть демо-данные |
| POST  | `/api/cards` | начать привязку карты → `{ redirectUrl, state }` |
| POST  | `/api/cards/:id/refresh` | уточнить статус привязки у провайдера |
| DELETE| `/api/cards/:id` | отвязать карту |
| POST  | `/api/sms-link` | выдать личную ссылку для пересылки уведомлений банка (старая перестаёт работать) |
| DELETE| `/api/sms-link` | отключить пересылку |
| POST  | `/api/ingest/:token` | текст SMS/push банка: `text/plain` или `{ "text": "…" }` |
| POST  | `/api/webhooks/bank` | уведомление банка об оплате (см. ниже) |
| POST  | `/api/webhooks/bepaid` | уведомление bePaid о привязке карты |

### Уведомление банка об оплате

```http
POST /api/webhooks/bank
X-Kopi-Timestamp: 1792316400
X-Kopi-Signature: hex(HMAC-SHA256(BANK_WEBHOOK_SECRET, "<timestamp>.<тело запроса>"))

{ "id": "bank-tx-123", "type": "purchase", "card_ref": "<ref карты>", "amount": 640,
  "currency": "BYN", "merchant": "Кофе", "created_at": "2026-10-18T09:00:00Z" }
```

`amount` — в копейках. Подпись старше 5 минут отклоняется. Повтор с тем же `id` возвращает `{ "duplicate": true }` и ничего не меняет. Операции не в BYN и не покупки игнорируются. Когда копилка набирает порог, списание и покупка идут в фоне — банку отвечаем сразу. Формат — наш; под API конкретного банка-партнёра понадобится адаптер.

## Что нужно для настоящих денег

- **Банк-партнёр** — источник оплат по карте (выпуск своей карты или API существующей). Подключается адаптером к `/api/webhooks/bank`.
- **Эквайер** — договор с bePaid (или другим провайдером) и ключи магазина. Формат запросов bePaid взят из документации docs.bepaid.by; разбор ответа токенизации нужно проверить на тестовом магазине.
- **Криптоплатформа — резидент ПВТ** — договор и ключи торгового API. Адаптер реализует `buy()` из `server/broker.js` и подключается в `brokerFromEnv`.
- **Юридическая часть** — KYC/AML, персональные данные, пользовательское соглашение.

## Деплой на Railway

Сервис собирается из репозитория без настройки (`railway.json`: старт `npm start`, healthcheck `/api/health`).

- **SQLite (как сейчас):** к сервису подключается volume, например с путём `/data`, сервер кладёт `kopi.db` в `RAILWAY_VOLUME_MOUNT_PATH`. Существующая база обновится миграциями при первом запуске.
- **PostgreSQL:** добавьте в проект Railway Postgres и передайте сервису `DATABASE_URL=${{Postgres.DATABASE_URL}}`. Таблицы создадутся сами. Данные из SQLite автоматически не переносятся — демо создастся заново.
