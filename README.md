# KOPI — инвестиции со сдачи

Каждая оплата картой округляется вверх, сдача копится в копилке и одним пакетом покупает BTC, ETH или консервативный рублёвый инструмент по реальному курсу.

## Что сделано

- **Эмулятор оплаты и round-up движок.** Касса принимает сумму, сервер округляет до 1/5/10 BYN с множителем ×1/×2/×5 и кладёт сдачу в копилку (`server/engine.js`).
- **Пакетная покупка по реальному курсу.** Когда копилка набирает порог (10/20/50 BYN) или нажата «Купить сейчас», вся сдача покупается одной операцией. Курс берётся как CoinGecko (USD) × официальный курс НБРБ, кэшируется на 30 с, страница обновляет курс и портфель каждые 30 с, а каждое получение пишется в БД. Если API недоступно, используется последний сохранённый курс (`server/rates.js`).
- **Дашборд накоплений и цели.** Стоимость портфеля, доходность по каждому активу, копилка, прогресс цели и прогноз в месяцах.
- **Кликабельное демо сценария покупки.** Пресеты покупок, чек, push-уведомления, сброс демо к «неделе покупок Ивана».

## Запуск

Нужен Node.js 24 (используется встроенный `node:sqlite`, внешних зависимостей нет).

```bash
npm start          # http://localhost:3000
npm run dev        # с перезапуском при изменениях
npm test           # тесты движка и API
```

Переменные окружения: `PORT` (по умолчанию 3000), `DB_PATH` (по умолчанию `data/kopi.db`).

## База данных (SQLite)

| Таблица     | Что хранит |
|-------------|------------|
| `users`     | пользователь и последние 4 цифры карты |
| `settings`  | шаг округления, множитель, актив, порог пакетной покупки |
| `goals`     | цель накопления (название, сумма) |
| `payments`  | оплаты: сумма, округление, сдача; `purchase_id` пуст, пока сдача в копилке |
| `purchases` | пакетные покупки: актив, сумма, курс, количество, источник курса |
| `rates`     | история полученных курсов BTC/ETH в BYN и курса USD НБРБ |

Копилка не хранится отдельно: это сумма сдачи по оплатам без `purchase_id`. Покупка в одной транзакции создаёт запись в `purchases` и привязывает к ней эти оплаты. Все суммы хранятся в копейках (целые числа).

## API

| Метод | Путь | Описание |
|-------|------|----------|
| GET   | `/api/state` | всё состояние дашборда |
| GET   | `/api/rates[?refresh]` | текущий курс |
| POST  | `/api/payments` | `{ merchant, amount: "6,40" }` или `{ amountKop: 640 }` — оплата с округлением |
| POST  | `/api/purchases` | купить сейчас на всю копилку |
| PATCH | `/api/settings` | `{ round_step, multiplier, asset, threshold }` |
| PUT   | `/api/goal` | `{ name, target }` (target в копейках) |
| POST  | `/api/reset` | вернуть демо-данные |

Демо работает с одним пользователем: авторизация и реальное списание остаются следующим этапом.

## Деплой на Railway

Сервис собирается из репозитория без настройки (`railway.json`: старт `npm start`, healthcheck `/api/health`). Для постоянной базы к сервису подключается volume, например с путём `/data`: сервер сам кладёт `kopi.db` в `RAILWAY_VOLUME_MOUNT_PATH`. Без volume база будет стираться при каждом деплое.
